## 一、产品总览

**Easy酒馆Pro** 是一个运行在浏览器中的 AI 角色扮演沙盒：创建任意 AI 角色卡，让它们与你对话、互相互动，并用世界书、记忆蒸馏、模块化 Gal/RPG 状态引擎、MVU 变量状态、智能生图等机制搭建完整的故事世界。

| 核心特性 | 说明 |
|---|---|
| 🎭 双角色引擎 | 对话同时绑定角色 A + 角色 B，各自独立角色卡、模型、气泡颜色 |
| 🔒 纯本地优先 | 所有数据存浏览器 IndexedDB，不请求任何后端；API Key 存独立密钥保险库 |
| 📦 单文件 PWA | 构建产物为单个 `index.html`，双击即用，支持离线 |
| 🧠 记忆体系 | 蒸馏 → 记忆结晶（累计摘要）→ 记忆回廊（可编辑）→ 手动植入 |
| 📖 双世界书 | 手动 A 书 + AI 自动维护的缓存书（上限 10 条，支持升华）|
| 🧩 模块化 Gal/RPG 引擎 | 独立书记 AI 按字段模块维护结构化状态（世界横幅/角色面板/背包/事件等）|
| 🧠 MVU 兼容 | 兼容 SillyTavern 生态变量协议，AI 维护持久状态 |
| 🖼️ 智能生图 | 气泡级生图入口，4 种渠道（OpenAI / NovelAI / Nano Banana / ComfyUI）+ 后台任务 |
| ☁️ 云同步 | 本地 JSON / OneDrive / Dropbox / GitHub Gist / WebDAV |

## 三、快速上手（4 步）

> ⚠️ **先会用浏览器打开**：Easy酒馆Pro 是 HTML 文件（手机/电脑免安装）。**必须用浏览器打开**（Chrome/Edge/Firefox/Safari/手机浏览器）；不要用记事本等文本工具打开——那样只会看到源代码。双击无效时，右键 →「打开方式」→ 选择浏览器。

1. **配 API**：右上角 ⚙️ 设置 → 模型管理 → 「添加」→ 填写 Base URL、API 模型名，绑定命名密钥或直接粘贴 API Key（会自动存入本机密钥保险库）。
2. **建角色**：侧边栏「角色」→「添加」→ 填角色名、System Prompt（可选开场白）。
3. **建对话**：侧边栏「对话」→「新建对话」→ 填标题，选择角色 A / B（可分别配模型）→「创建」。
4. **发消息**：聊天输入框输入内容，按 **Shift+Enter 发送给角色 A**，或点「发送A」「发送B」按钮。

> 💡 首次打开应用会自动注入「核桃 & 花生」鼠族教学预设（含角色卡、世界书、无密钥模型模板），可直接按内置教学对话一步步上手。

## 四、对话与消息

### 4.1 消息输入区（ChatInput）

- **角色模型摘要栏**：显示 `A:角色名(模型) | B:角色名(模型)`，点击打开「角色与模型设置」弹窗；右侧 ⚙️ 设置按钮。
- **输入框**：Enter 换行，**Shift+Enter 发送给角色 A**；流式输出时禁用。
- **主操作按钮**：
  - 「发送A」（主按钮）、「发送B」：仅发送给对应角色；
  - 「同时告知」（旁听）：同一条消息按 A 后 B 顺序分别请求，两角色读取**相同的发送前对话快照**（B 不会先看到 A 的新回复）；
  - 「⏹ 停止」：流式输出中显示，中断本次流式请求。
- **副 AI 状态条**（输入框上方）：发送前预告本条会触发状态书 / 缓存世界书 / 记忆蒸馏；执行时显示副 AI 模型名与当前任务，避免误认为页面卡死。
- **📝 工具箱**（折叠工具栏）：
  - 🧠 **深度思考**：开关，开启后发送时附带 `reasoning_effort: medium`（DeepSeek 等支持思考模式的服务商生效）；
  - **流式输出**：开关，关闭后一次性接收完整回复（对部分模型与 MVU 稳定性更好）；
  - 🧬 **植入记忆**：开关，开启后下一条消息自动把最近的记忆结晶 + 状态书作为 system 消息植入；
  - 🤝 **互相认识**：让两个 AI 观察对方角色卡互写印象（详见第十二章）；
  - 📜 **状态书**：跳转状态书视图；
  - **蒸馏**：手动触发记忆蒸馏；
  - 📖 **记忆回廊**：打开记忆结晶列表弹窗，逐条编辑；
  - **表情包**：打开本对话角色表情包绑定弹窗。

### 4.2 消息气泡（MessageBubble）

- 发送者标签（👤 你 / 角色名）+ 头像 + 时间戳；AI 内容经 Markdown 渲染。
- **Token 统计**（AI 消息）：显示 `✨ N Tokens`（API 精确值）或 `⚡ N Tokens`（估算值）；悬停显示明细：📥 输入、📤 输出、🧠 思考（含于输出）、🪙 总计、📜 状态书消耗。
- 用户消息显示**本次激活的世界书条目**名称与预估 Token；手动植入记忆的消息带「🧬 已植入记忆&状态书」标记。
- **悬停操作栏**（AI/用户消息）：
  - 「分支」：以此消息为起点克隆出平行对话（仅 AI 消息）；
  - 「编辑」：进入编辑态，可同时修改文本、状态书文本、Galgame 数值；
  - 「重新生成」：删除该 AI 回复（及其后消息）并复用原用户消息重发（仅 AI 消息）；
  - 「删除」：删除单条消息（附带状态书一并删除，有确认提示）。

### 4.3 消息列表（MessageList）

- **分页加载**：默认只渲染最新 80 条，顶部出现「加载更早消息」按钮，加载后保持滚动位置。
- **进度跳转条**：长对话时右侧出现 5 个半透明竖向胶囊（顶部 / 25% / 50% / 75% / 底部），点击平滑跳转。
- **智能滚动**：仅当靠近底部时自动跟随；**长对话切换后恢复原滚动位置**，不自动跳回顶部或强制滚到底部。
- 流式输出显示占位气泡（角色头像 + 实时内容 + 脉动光标）。
- 记忆结晶以独立的琥珀色虚线卡片（DistilledBubble）渲染，带「复制」「插入上下文」按钮。

### 4.4 新建对话

- 弹窗内容：标题、**用户名称**（替换角色卡中的 `{{user}}` 占位符）、一句话描述（可选，v1.39 新增）。
- 角色 A / B 两个槽位切换点选，选择 A 后自动切到 B 槽；A、B 缺一不可。
- 空白对话首次加载角色时自动插入其「第一句预设对话」（按角色 A → 角色 B 顺序加载，防止重复生成）。

### 4.5 对话导出

- 对话卡片悬停「导出 TXT」：导出当前对话全部消息为纯文本文件。

## 五、角色管理

### 5.1 角色列表

- 卡片显示：头像（图片 / emoji）、名称、System Prompt 摘要（2 行截断）、「A 世界书 / 缓存世界书」绑定标签。
- 悬停操作：导出为酒馆格式 JSON、编辑、删除（删除有确认，警告已绑定对话将无法正常使用）。

### 5.2 添加 / 编辑角色

- **头像**：上传本地图片（自动压缩至 480px）或直接输入 emoji（最多 2 字符）。
- **角色名 / System Prompt / 第一句预设对话**（v1.39：空白对话首次加载时自动生成该预设气泡）。
- **绑定 A 世界书**（手动书）与 **绑定缓存世界书**。
- **创建对话时自动启用 MVU**：开关；导入 SillyTavern V2 卡时默认开启。

### 5.3 导入角色卡

- 支持 **SillyTavern V2 / Character Card V2 格式**：`.png`（PNG tEXt/iTXt 隐写）与 `.json`。
- 导入自动还原：角色卡 → 世界书（character_book）→ 开场白（first_mes）→ 示例对话（mes_example）；v1.39 兼容 `alternate_greetings`（备选开场白）、`creator_notes`、`system_prompt`、`post_history_instructions`、`tags`、`creator`、`character_version` 等字段；有兼容性提醒。
- **兼容性**：不同制卡工具/版本/扩展字段存在差异，**不能保证 100% 兼容**，通常约 **80% 内容可正常识别**；PNG 被压缩、二次导出或社交平台转码可能破坏隐藏 JSON，导入异常时优先用原始 PNG。
- **编码容错**：导入过程含数据验证、编码检测与错误回调，兼容部分 GBK、Latin-1 和异常中文文件。
- 支持「导出为酒馆格式 JSON」分享（其他用户在同一页面点「导入」加载；导出的 JSON 便于备份与跨平台分享）。
- 导入后建议检查：角色名称、头像、主提示词、首条消息、示例对话、世界书关联。

### 5.4 Easy人物卡组装器（🧩 模块化组装）

点「🧩 Easy人物卡 · 模块化组装」进入向导，**7 个模块勾选/填选**后自动拼装完整 System Prompt：

| 模块 | 内容 |
|---|---|
| 1. 🧭 引导头 | 5 种预设（沉浸式单兵 RP / 互动群像叙事 / 协同剧本创作 / 经典 TRPG 跑团 / 神秘科技）或手写 |
| 2. ✍️ 文风部 | 12 种文风标签多选叠加（唯美叙事、市井白话、二次元轻小说、冷硬派、意识流、都市霓虹、仙侠玄幻、传统武侠、白描、克苏鲁、黑暗、末日） |
| 3. 🎯 核心人设 | 手写 + 「🔍 一键复制 AI 搜索提示词」模板 |
| 4. 🛡️ 安全词/金手指 | 括号 OOC 控制法 / 剧情快退锚点 / 状态清空安全词 / 金手指 root 权限 |
| 5. ⚙️ 逻辑·防退化·防神化 | 角色主观视角 / 拒绝复读机 / 防神化（输出为 `<SYS_CONSTRAINTS>` XML） |
| 6. 📝 回复示范 | 期望的回复范本 |
| 7. 📋 输出要求 | 标准 RP 250-450 字 / 破冰开局 / 轻量化 150 字 / 剧情选项功能 |

底部支持「👁 预览拼装结果」后保存为角色卡。

### 5.5 高级卡逆向

- 仅编辑模式且已绑定世界书时显示；红框说明效率约 60%~80%，结果会覆盖主提示词。
- **适用条件**：角色卡**没有主提示词、只有世界书或零散设定**时才用；已有完整主提示词的正常卡**不要点击**（会额外消耗 AI 请求并可能改写原本正常的设定）。
- 使用**蒸馏模型**执行，默认开启思考模式 medium；执行中显示进度弹窗（请勿关闭窗口）。
- 错误分类提示：鉴权 / 限流 / 网络 / 内容拒绝。

## 六、模型管理

### 6.1 模型通道列表

- 模型卡片显示：名称、`defaultModel @ baseUrl`、最大上下文 N tokens、采样预设徽章（🎨异想天开 / ⚖️中规中矩 / 📐严格规矩 / 🔄无设置）或 `T= / P=` 参数。
- 每卡片按钮：「Ping」延迟检测、「蒸馏」（高亮=当前蒸馏模型）、「编辑」「删除」。

### 6.2 添加 / 编辑模型

- **自定义模型名称 / Base URL / API 模型名**。
- **获取模型**（v1.39）：调用 OpenAI 兼容 `/models` 接口生成模型下拉列表；保留手动填写，兼容不提供列表接口的服务商。
- **一键复制渠道**（v1.39）：复制地址、密钥引用和参数，自动命名为副本。
- **密钥绑定**：从密钥管理器下拉选择命名密钥，或直接输入新 API Key（自动存入保险库，可命名）；导出/同步永远不包含密钥。
- **最大上下文 Token 数**：自动钳制 ≥1000，决定上下文截断预算。
- **采样参数**：4 个预设卡片（异想天开 T1.2/P0.98 · 中规中矩 T0.8/P0.92 · 严格规矩 T0.3/P0.85 · 无设置 -1）+ Temperature (0-2) / Top-P (0-1) 手动输入。
- **思考模式 / 流式输出**：可按模型或对话控制（v1.39）。
- 新模型创建后若未指定蒸馏模型会自动设为蒸馏模型；生图提示词模型采用与蒸馏模型一致的勾选式绑定。

### 6.3 Ping 与连接问题速查

- 每卡片「Ping」按钮测试延迟：正常显示 ms；失败分类：超时 / Error / CORS / HTTP 状态码。
- 「常见模型连接问题」折叠卡片：HTTP 400 / 401·403 / 404 / 429 / 5xx / 超时 6 类错误速查 + CORS 专项说明（本地文件版为何报 CORS 及 3 条解决建议）。

## 七、世界书

### 7.1 概念

世界书（Lorebook）是「按需注入的设定小抄」：词条带关键词/别名，聊到相关内容才注入上下文，平时不占 Token。

- **适合放入**：次要人物/NPC、特殊道具/武器/药剂/载具、世界观/地理/历史事件。
- **不适合放入**：核心 AI 的性格、外貌、行为边界、与玩家的亲密关系——这些应写在角色卡主提示词（System Prompt）里，不要只放世界书。
- **与角色卡的关系**：Easy世界书（批量创建+按关键词注入）与 Easy角色卡（导入/组装/编辑人设）是两个独立功能，可关联使用但不能混为一谈；API 负责生成回复，角色卡负责"角色是谁"，世界书负责"世界里有啥"。

### 7.2 双世界书体系

| 类型 | 说明 |
|---|---|
| **手动 A 书** | 玩家手动维护的核心设定，常驻绑定到角色 |
| **缓存书** | AI 自动维护的动态笔记，上限 10 条，绑定角色后由状态书/Galgame 引擎按 JSON 协议维护 |

### 7.3 世界书管理页

- 顶部「📖 Easy世界书 + 新手教程」：内置教程弹窗（世界书原理 + AI 自动蒸馏 4 步）+「⚡ 一键复制 AI 生成命令」。
- **手动世界书列表**（「新建」按钮）与 **缓存世界书列表**（青色标题区「新建缓存」）。
- 每个世界书卡片：点击头部展开/折叠；显示名称、条目计数（缓存书带 `/10` 上限）、「缓存」徽章；「+」添加条目、「🗑」删除。
- 展开后条目列表：关键词标签（琥珀色）+ 优先级 + 内容摘要；每条操作：编辑、删除；**缓存书条目有「升华」按钮**（并入绑定角色的 A 书并从缓存书移除）。

### 7.4 条目字段

- **触发关键词**：逗号或中文逗号分隔多个关键词/别名。
- **注入内容**：命中关键词时注入的设定文本。
- **优先级**（1-10）：越高越优先注入。
- **常驻（alwaysActive）**：无关键词也每次注入（导入 V2 卡的 constant 条目）。

### 7.5 批量导入 / 导出

- 「粘贴 JSON 批量导入」：容错剥离 ` ```json ``` ` 代码块；缓存书还支持 `{"operations":[...]}` 修改对象格式。
- 「导出 JSON」：复制到剪贴板。
- 关键词命中采用防 ReDoS 扫描：字面量包含快速路径 + 正则转义兜底。
- **扫描机制**（v1.39）：废除旧「世界书插入冷却」，改为「**扫描深度 + 最大插入条目**」——扫描深度决定向前回读多少条历史 user 对话及其间的角色回复与记忆；最大插入条目决定一次最多向模型提交多少条命中设定。世界书正文只在最终请求阶段组装，不写入历史消息。

## 八、模块化 Gal/RPG 状态引擎

### 8.1 是什么（v1.39 重组）

原「文本状态书 + Galgame 数值引擎」在 v1.39 重组为**模块化 Gal/RPG 引擎**：独立的「书记 AI」根据你启用的字段模块拼接提示词，只输出**本轮变化的合法 JSON**，附着在角色回复气泡下方（已属性化，随历史线性注入上下文）。旧状态书和 Galgame JSON 会自动迁移到兼容字段中，升级后仍可查看。

**入口**：侧边栏「状态书」视图（每对话独立配置）。

### 8.2 可启用模块

| 模块 | 内容 |
|---|---|
| 世界横幅 | 日期、地点、组织与势力 |
| 角色面板一 / 二 | 两个角色槽位可独立启用并填写角色名，书记 AI 按角色名维护对应 JSON |
| 生命 / 心情 / Buff / 自定义货币 | 数值子面板（生命红、心情青、货币金三色调） |
| 背包与物品栏 | 随身物品列表 |
| 角色关系 | 对主角关系 + 人物关系网 |
| 事件栏 | 任务日志（「进行中」状态带脉动圆点） |
| 配角栏 | 场景配角信息徽章 |
| 自由文本 | 备注说明 |
| 身体状态 | 头/躯干/四肢 14 个部位，健康/轻伤/重伤/缺失四色显示（深色「体魄」面板 + 伤处发光） |
| 身体特殊状态（默认关闭） | 按角色 A/B 绑定、按部位多状态、粉色描边叠加、点击部位查看预设文本 |

### 8.3 配置项

- 「启用状态书」「维护缓存世界书」开关；
- **插入策略模式**：仅角色 A / 仅角色 B / 自动（就近）；
- **书记模型**：独立下拉选择（第三书记员专用通道，不占用角色模型额度）；
- **触发间隔**（每 N 轮触发一次，默认 5，可调 1-50）；
- **每次总结的对话轮数**（默认 4，最低 2）；
- 「立即更新模块」手动触发；
- **模块维护提示词**：整体可编辑；每个字段的维护提示词也可单独编辑（控制该字段的更新判断方式）。

### 8.4 组装预览车间

状态书页实时展示「组装预览」：与最终聊天气泡复用同一个 `ModuleRpgCard` 组件，布局完全一致（RPG HUD 风格：世界横幅 / 体魄面板 / 属性子板 / 背包 / 任务日志 / 配角徽章）。开关任意字段，预览立即增减对应区域。

### 8.5 工作原理

- 书记 AI 只接收：基础提示词 + 启用面板规则 + 启用字段维护规则 + **当前合法状态（只读）** + 近期对话，只返回本轮变化字段；
- `parseModuleRpgResponse` 多级兜底解析（直接 JSON → 正则提取 → 容错修复 → 字段校验）；
- `mergeModuleRpgSnapshot` 字段级白名单校验合并：**非法字段 / 非法身体状态不会覆盖原数据**，解析失败时保留上一份快照并显示诊断；
- 状态范围 = 角色 ID + 对话槽位（A/B），同一张卡绑 A/B 两槽时状态互不干扰；
- 编辑气泡可直接篡改模块 JSON：点击模块卡「✏️」进入 JSON 编辑，保存合法字段；
- **不推荐与 MVU 同时开启**（两套状态维护器会重复记录同一剧情，增加费用并可能矛盾）。

## 九、MVU 变量状态引擎

### 9.1 是什么

MVU（Memory Variable Update）是 SillyTavern 生态的「变量状态」协议：角色卡通过 `[InitVar]` 定义初始变量，AI 在每次回复末尾输出 `<UpdateVariable>` 更新块来维护持久状态（物品、属性、任务、关系等）。

### 9.2 兼容能力

- **自动识别**世界书中的控制条目：`[InitVar]`（初始化）、`[mvu_update]` / `[mvu_plot]`（更新规则）；
- **协议解析**：
  - JSON Patch（RFC 6902，`{"op":"replace","path":"/x","value":...}`）；
  - 脚本式 `_.set() / _.add() / _.assign() / _.remove() / _.move()`（解析为安全操作，**不执行任何脚本**）；
  - 混合卡优先使用明确 JSON Patch 规则；
- **InitVar 多格式兼容**：JSON5 / YAML / 嵌入式对象 / 带前置说明文本的对象，全部安全解析；
- **快照断点**：每 8 个有效回复保存一次完整快照，其他节点只存变更操作；分支按各自时间线回放；
- **本地协议校验**：旧值不匹配、路径不存在等非法操作被拒绝并记录诊断；校验失败不会污染状态；
- **DeepSeek 兜底**：回复未输出更新块时，自动发起一次独立的「MVU 状态维护」请求（JSON-only），保证状态不丢失。

### 9.3 使用方式

1. 角色卡（或其绑定世界书）包含 `[InitVar]` / `[mvu_update]` 条目；
2. 开启 MVU：设置 →「启用 MVU」全局默认，或角色卡勾选「创建对话时自动启用 MVU」，或在状态书视图 MVU Tab 中按对话开启；
3. 对话中正常游玩，AI 回复后可在气泡下方看到可折叠的「MV 状态」条（字段表格 + 本轮变更 + 诊断）。

### 9.4 MVU 面板（状态书视图 → MVU Tab）

- 每个角色一张状态卡：绑定世界书名、`InitVar 条数`、`更新规则条数`、`状态回复数`；
- 「编辑状态」：直接修改当前 JSON 状态（保存为新的 checkpoint）；
- 「重置为 InitVar」：恢复初始变量；
- 显示「最近变更」列表（路径: 旧值 → 新值）与「初始化诊断」；
- 「MVU 变量状态控制提示词」文本域可编辑（需保留 `{state}` `{schema}` `{rules}` `{protocol}` 占位符）。

### 9.5 注意事项

- 状态作用域 = 角色 ID + 对话槽位（A/B），同一张卡绑定 A/B 两槽时状态互不干扰；
- 只在当前状态中已存在的字段上更新，不凭空创造功法/法宝/任务；
- 回复中未闭合的 `<UpdateVariable>` 标签会在流式显示时被隐藏，解析失败记录诊断。

## 十、记忆蒸馏与记忆回廊

### 10.1 什么是记忆蒸馏

长对话压缩成「记忆结晶」（distilled 节点），替代原始消息参与上下文——AI 不丢早期设定，同时控制 Token 消耗。

### 10.2 触发方式

- **手动**：输入区工具箱「蒸馏」按钮。
- **自动**：设置 →「自动触发蒸馏」开启（阈值满足时自动执行）。

### 10.3 规划规则（完整轮次）

- 只蒸馏**完整轮次**（user 消息 + 至少一条角色回复），不拆开 user 与回复、不产生单轮小批次；
- 默认阈值 10 轮、保留最近 3 轮 → 至少 13 个完整未归档轮次才会执行；
- 不足阈值时提示「完整可蒸馏轮次不足」。

### 10.4 安全保护

- 会话内单任务互斥（并发触发不会重复执行）；
- 提交时复核来源节点（已归档/不属于本对话则拒绝）；
- 归档与结晶写入在同一锁内完成，失败自动回滚；
- 空摘要不会归档原对话；
- 蒸馏输出兼容 `content` / `text` / `reasoning_content` 等返回结构。

### 10.5 记忆回廊

- 输入区工具箱「📖 记忆回廊」打开弹窗；
- 按时间正序展示所有记忆结晶（`#n` + 时间），每条可「编辑」（多行文本域，内容不能为空）；
- **累计摘要机制**：新结晶是「累计摘要」（包含此前全部内容），上下文只注入最新一份，减少重复 Token；
- 编辑最新累计结晶会直接影响后续上下文；历史结晶作为快照保留。

### 10.6 蒸馏配置（设置 → 记忆蒸馏）

- 最少完整对话轮数（5~50，触发阈值）；
- 滑动窗口·保留最近（0~15 轮）；
- 自动触发开关；
- 蒸馏提示词模板（`{dialogue}` 占位符）。

## 十一、表情包系统

### 11.1 概念

AI 在回复正文中通过 `<EJP_STICKER>{"id":"表情ID"}</EJP_STICKER>` 协议调用本地表情包，按插入位置渲染在气泡内；调用字段不会进入后续上下文。

### 11.2 管理（设置 → 高级表情包设置）

- **总开关**「启用表情包功能」；
- 全局最多 **2 组**，每组最多 **8 张**；
- 上传格式：png / jpeg / webp / gif；静态图自动压缩（最长边 512px，WebP 82%）；**GIF 需 ≤1.8 MiB**；
- 每张图可编辑标签（建议用清晰情绪/动作词，如「开心」「惊讶」）；支持改名、删除；
- 提示：本地图片只存在浏览器 IndexedDB，不会发给 API。

### 11.3 绑定与使用

1. 对话输入区「📝 工具 → 表情包」：分别为角色 A / B 绑定表情包组（关闭/选择）；
2. 全局「每次回复最多调用数量」可调（默认 2）；
3. AI 回复生成时会看到「只读可用表情 JSON 清单」并主动调用；
4. 表情包控制提示词可在高级提示词模板中自定义。

### 11.4 容错

- 模型编造的 ID 会被拒绝；重复调用去重；解析失败时协议块从正文剥离，不污染对话。

## 十二、智能生图系统（v1.39 新增）

### 12.1 入口

每个 AI 对话气泡下方「生图」入口。气泡决定向上扫描截止点和图片插入位置；生成图片插入对话时间线，支持删除、导出与重新生成。

### 12.2 配置（设置 → 生图设置）

- **生图渠道**（独立于文字主渠道，支持测试图片按钮验证连通性）：
  - OpenAI 兼容 `/v1/images/generations`；
  - NovelAI 官方图像协议；
  - Nano Banana / Gemini 原生图像协议；
  - ComfyUI API 工作流（导入 API 格式工作流 + 手动或 AI 生成映射草案；正式生图只做字段替换，不额外消耗 AI）。
- **提示词组装 AI 模型**：独立勾选绑定（与蒸馏模型一致的方式）。
- **一句话核心画面描述 + 历史扫描轮数（1-10）+ 比例（1:1 / 3:4 / 16:9）+ 画风（国风仙侠 / 二次元 / 真人 / 美漫 / 自定义）+ 安全模式**。
- 提示词组装 AI 会结合：玩家一句话（最高优先级）→ 指定历史轮次 → 当前角色卡人设 → 角色绑定世界书命中内容 → 比例与画风参数；提炼后提供中文正向/反向提示词**预览，可手动编辑再提交**。
- 安全模式在不改变核心剧情和构图的前提下，将敏感表达改写为适合官方生图渠道的版本。

### 12.3 后台任务

- 生图任务进入后台后可继续聊天，顶部显示任务状态、等待时间与重试阶段；
- 失败任务可关闭、编辑提示词并重新生成（重新生成读取最新绑定的生图渠道，不锁死旧渠道）；
- 请求含长耗时等待、退避重试与超时说明（默认 720s），减少「服务端成功但前端判定失败」的问题。

- 面板会实时检测当前参数匹配的挡位并高亮；中/高耗保留用户当前状态书开关。

## 十八、同步中心与密钥管理器

入口：设置 →「同步中心 / 密钥管理器」按钮（两个 Tab）。

### 18.1 同步方式（5 种）

| 方式 | 配置 | 说明 |
|---|---|---|
| 本地 JSON | 无需配置 | 导出/导入同步包（离线搬移） |
| Microsoft OneDrive | 微软应用 Client ID + 登录 | OAuth PKCE；需 HTTP(S) 环境（本地 file:// 不可用） |
| GitHub Secret Gist | GitHub PAT（仅勾选 gist 权限）+ Gist ID（留空自动创建） | 按设备分别保存文件，下载选最新有效包 |
| Dropbox | Dropbox app key + 登录 | OAuth PKCE；需 HTTP(S) |
| 私人 NAS WebDAV | WebDAV URL + 用户名/密码（存密钥保险库） | 支持 ETag 条件写入 |

### 18.2 同步行为

- 「保存同步设置 / 上传同步 / 下载同步」三按钮；
- **冲突检测**：远端在本地上次同步后变化时，上传/下载会弹窗确认是否覆盖；
- **上传进度**：实时百分比、已上传大小、上传速度、预计剩余时间与取消按钮；上传达到 100% 后仍会等待服务商返回最终确认（避免把「数据已发送」误判为「远端已保存」）；
- **下载行为**：桌面端下载同步自动生成本地安全备份再覆盖导入；手机端为避免浏览器连续下载相同文件，改为明确提示玩家先手动备份；
- 远端路径可自定义（默认 `easyjiuguanpro-sync.json`）；GitHub Gist 按设备 ID 分离同步文件，选择最新有效数据；
- 同步包内含业务数据（模型/角色/对话/消息/世界书/状态/表情包），**绝不含任何密钥与调试快照**。

### 18.3 密钥管理器

- 「新增/编辑命名密钥」：名称 + 类型（API Key / 同步 Token / PAT / 同步账号或密码）+ 值（密码输入框）；
- 密钥列表：名称、类型、状态（已隐藏），支持编辑/删除；删除时提示被哪些模型引用；
- 密钥只存本机浏览器，**不出现在导出/同步包中**。

## 二十、备份与隐私

### 19.1 备份

- **导出数据**：设置 →「导出数据」，下载 `easyjiuguanpro-backup.json`（完整业务数据）；
- **导入数据**：「导入数据」选择 .json；导入前做表级结构校验；**自动清空所有 apiKey / secretId**，避免继承他人密钥。

### 19.2 隐私边界

| 数据 | 是否离机 |
|---|---|
| 对话/角色/世界书/状态 | 仅随你手动导出或同步 |
| API Key / 同步 Token / 密码 | 永不（存独立保险库） |
| 调试快照（Prompt/原始返回） | 不随导出（device-local） |
| 表情包图片 | 存 IndexedDB，仅导出时序列化 |

### 19.3 部署建议

- 本地直接双击 `dist/index.html` 使用（云同步 OAuth、GitHub 商店不可用）；
- 部署 GitHub Pages / Vercel / Netlify 可获得完整能力；GitHub Actions 已配置自动构建发布 `dist/`。

## 二十一、调试功能

- **开关**：设置 →「调试·提示词与原始返回下载」；
- 开启后 AI 回复气泡底部出现两个按钮：
  - 「📄 导出发送给该角色的原始 Prompt」(.txt)；
  - 「导出 AI 原始返回 JSON」（SSE 事件流/usage/finish_reason/reasoning_content 等完整快照）；
- Debug 导出标明**命中的世界书与预估 Token**，方便检查消耗来源；
- 调试快照为 device-local，不随导出/同步。
- **推理内容过滤**始终生效：兼容 `<think>` / `<thinking>` / `<though>` / reasoning / analysis / cot / scratchpad / planning 等 19 种标签（含大小写、属性、方括号、未闭合畸形变体），流式正文隐藏推理内容；模块化 Gal/RPG 与遗留引擎的 JSON 解析仍可从原始返回回退提取。
- 流式渲染使用帧合并，减少长回复频繁刷新造成的卡顿。

## 二十二、常见问题

**Q: 页面打开了但 AI 不回复？**  
检查：① 是否已配置 API；② API Key 是否有效；③ 模型名是否正确；④ 账户是否有额度；⑤ 新建对话时是否选中了正确的模型服务。

**Q: 没有角色卡怎么办？**  
可直接用内置的「核桃 & 花生」教学预设；也可在【角色】页导入 V2 PNG 角色卡，或用 Easy人物卡组装器自建。

**Q: 需要服务器吗？**  
不需要。构建产物是单个 HTML 文件，双击即可用；也可部署到任意静态托管。

**Q: 支持哪些模型？**  
兼容 OpenAI Chat Completions 格式的服务商（DeepSeek、OpenAI、智谱 GLM、豆包及各类代理），支持「获取模型」接口拉取列表。

**Q: 为什么发送失败/报错？**  
看输入区上方的错误横幅：常见 400（参数/格式）、401/403（密钥）、404（接口路径）、429（限速，自动重试）、5xx（服务端）、CORS（本地 file:// 环境常见，部署到 HTTP(S) 或使用支持 CORS 的代理）。

**Q: 为什么模块化 Gal/RPG 没触发？**  
检查：① 「启用状态书」开关开启；② 已选择书记模型（第三书记员独立通道）；③ 触发间隔轮数到了（默认每 5 轮）；④ 插入策略模式匹配当前回复角色；⑤ 检查副 AI 状态条的预告与执行提示。

**Q: 模块化 Gal/RPG 和 MVU 可以同时开吗？**  
不推荐。两套状态维护器会重复记录同一剧情，可能增加费用并产生矛盾。

**Q: 蒸馏提示轮次不足？**  
只蒸馏完整轮次：默认阈值 10 + 保留 3，需至少 13 个完整未归档轮次。

**Q: 编辑记忆回廊有什么影响？**  
编辑最新累计结晶影响后续上下文；历史结晶只是快照。

**Q: MVU 不更新？**  
确认角色卡含 `[InitVar]`/`[mvu_update]` 条目、MVU 已开启、回复中输出了合法 `<UpdateVariable>`（或 DeepSeek 走兜底通道）。

**Q: 表情包不显示？**  
确认总开关开启、已建组、对话中已为对应角色绑定、AI 调用的是真实 ID。

**Q: 生图失败怎么办？**  
先到「设置 → 生图设置」用测试图片验证渠道连通性；失败任务可关闭、编辑提示词并重新生成（重新生成读取最新绑定的渠道）。

**Q: 云同步提示冲突？**  
说明远端文件在本地上次同步后变化过，确认后再覆盖；多设备建议错开操作或换 Gist 按设备隔离模式。

**Q: file:// 打开时哪些功能不可用？**  
云同步 OAuth（OneDrive/Dropbox）、GitHub 角色商店需要 HTTP(S)；其余功能全部可用。
